# W3: Windows App Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new `apps` stage installs the selected profiles' GUI and CLI apps with winget, adopts apps already installed, and `verify` reports missing and undeclared apps; core also installs the JetBrains Mono Nerd Font.

**Architecture:** One data file (`profiles/apps.psd1`) declares every profile, its winget IDs and the default set. `script/lib/Apps.psm1` reads it; `script/lib/Winget.psm1` is the only place `winget list/install/export` run for apps, mapping winget's return codes to outcomes. `script/stages/Apps.psm1` loops over the selected packages (check, then install only what is missing, continue past a failure). `script/lib/Font.psm1` installs the font per user from the upstream release, verified by SHA256. Verify gains an apps check, a font check and an informational drift line.

**Tech Stack:** PowerShell 7.6+, winget CLI, Pester 6.2.0, PSScriptAnalyzer 1.25.0 (repo gate `script/test.ps1`).

**Spec:** `docs/superpowers/specs/2026-11-24-setup-dev-win-linux-design.md` (sections 6.4, 6.5, phase W3), with operator decisions of 2026-11-26 recorded in `TASKS.md` and below.

## Review Focus

1. A machine whose `state.json` persisted `profiles = core` from milestone 1, re-run with no `-Profiles`: the apps stage prints the profiles in use and how to change them (`-Profiles core,dev,...`), so the operator is not left wondering why VS Code is missing. Test in Task 3.
2. An app installed by hand that `winget list` does not correlate: the install is attempted and the installer reports "already installed" (`-1978335135` or `-1978334963`, or `-1978335189`); that is success, not a failure. Test in Task 2.
3. One package fails (hash mismatch, network, a declined UAC prompt): the others still install, the stage returns `failed` naming every failed ID and its reason, and a re-run tries only what is still missing. Tests in Task 3.
4. `winget list` truncates long IDs in its table and localises its text: detection uses the exit code only, never the printed table. Test in Task 2.
5. Adding a profile later (`-Profiles ...,local-llm`) after a run where `apps` was recorded `done`: the apps stage runs again on every setup run (like verify), so the new profile installs. Test in Task 3.
